# Validation status

Version 0.9.0 adds grouped paginated unread triage for chats/channel threads, batch context refresh and explicit native quoted chat replies. Replies revalidate context, retain durable duplicate protection across restart, and report send/read stages separately. Candidate channel replies and conservative read-after-reply are implemented but **disabled** pending verified native Teams write captures and designated-conversation validation; fixtures do not establish compatibility. Regression tests cover ordering, account isolation, partial coverage, context races, ambiguous sends, disk failures, sibling-thread protection and old roots in truncated reply windows. See [protocol evidence and gates](docs/triage-protocol.md).

Read-only triage live check on 2026-10-08: initial silent authentication returned `signin_required`. After interactive Microsoft Authenticator approval, the API returned ten inbox groups (with nine explicit coverage issues and further pagination available), and three reply-context refreshes succeeded. Browser authentication closed before those API reads. This establishes bounded chat inbox/context compatibility, not channel completeness or write behavior. The user subsequently designated the self/Notes chat for live writes. Storage-preserving native capture retries encountered browser timeouts; the final worker/network-only attempt captured conversation-service authentication but no regional chat token, and stopped before any test sends. Channel writes were not designated. Native quoted sends and read-marker writes remain to be live-validated.

Version 0.8.1 adds `npm run auth:sync`: laptop-side status/expiry checks, server HTTP renewal through a read-only probe, saved-session/interactive browser acquisition when necessary, in-memory reconnect upload, and post-upload status verification. Fixture tests cover healthy skips, terminal versus transient renewal failures, forced/silent acquisition, cancellation, target validation, upload rejection and secret-free output. Live sync against the central Switchboard remains to be tested.

Version 0.8.0 integrates the live-validated browser capture and HTTP renewal helpers into production authentication, portable version 2 token exports/imports, on-demand renewal and restart recovery. Switchboard stores returned refresh-token rotations encrypted. A partial renewal failure returns updated credentials for storage and blocks the requested Teams operation. Imported connections never launch a browser; terminal rejection requires re-export. Version 1 access-only bundles remain supported. Fixtures cover production acquisition, rotation, partial failures, forced renewal, restart, transient versus terminal errors and existing-account preservation on failed imports.

Live validation on the user's Mac, 2026-10-08: the visible Teams sign-in required Authenticator approval and yielded a refresh token through `authorization_code`. The diagnostic confirmed browser-process exit, renewed both Skype and chatsvcagg access tokens through Node HTTP requests, followed refresh-token rotation, passed the Teams chat-token exchange/account check, and passed profile and conversation reads. No captured tokens were exported or saved by the diagnostic, and it sent no messages. Initial headless saved-session attempts captured no Microsoft token exchange; silent browser reacquisition is not validated. This live PASS establishes the first compatibility gate, not refresh-token lifetime, expiry-cycle recovery, cookie-only renewal or central-host compatibility. Production integration and versioned portable bundles are implemented with fixture coverage. Production central-host testing and recovery after refresh-token expiry remain outstanding.

The production adapter uses Teams APIs with either local browser authentication or imported tokens for a browser-free host. Token export/import, server-side token validation, HTTP renewal, restart recovery and ledger retention have fixture coverage; a real export has passed read-only token exchange, account binding and conversation validation on the authentication machine; central-host import still needs live validation. The earlier Go probe validated real token acquisition and three read operations. The new Node adapter needs its read-only live check and tenant-specific silent-renewal check run on the user's Mac.

Remaining API migrations are message search, new-chat creation, exact-person mentions, unread marking, and live verification/enabling of channel replies and read markers. Native quoted chat replies and channel-thread reads are available through the triage helpers; the legacy `replyToMessageId` parameter remains unsupported. Attachments remain unsupported. Unsupported operations are excluded from OpenAPI or return an explicit per-target failure in mixed batch helpers, and are reported by getTeamsCapabilities. They must acquire verified API contracts and meaningful tests before being advertised as supported.

Further validation: designated-chat live writes, pagination on large accounts, token renewal across tenant sign-in policy expiry, and independent code review. No live write should be inferred from fixture test success.
